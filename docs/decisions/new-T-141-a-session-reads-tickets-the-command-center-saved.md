## D-T-141 A session reads the tickets the Command Center saved (2026-10-28)

An agent in a terminal session could not see a project's live board: the Command Center holds each tracker's sign-in in VS Code's secret storage, one per repo (D-027), and a session can't reach it. A second sign-in for the session (an Azure CLI or MCP token) was turned down: a user-wide token reaches every client's tracker, which D-027 rules out. The person chose this route instead: the Command Center writes what it already reads where a session can read it.

- **Where.** One file a ticket, `<git dir>/acc/tickets/<key>.json`, beside `boards.json` in the repo's own state folder. Never committed. One file a ticket, so each is saved as soon as it is read, written whole (temp file, then rename), and a queue stopped part-way loses nothing. No file holds a sign-in or a token: a ticket is keyed to its tracker by the tracker's settings as written, as `boards.json` keys boards (`trackerKey`).
- **Shape.** The ticket a plan reads (`planTicket`, T-110): description as markdown, comments oldest first, related tickets, attachment names, and the changes field (T-105) where the tracker names one. Azure DevOps' acceptance criteria and repro steps are in the description, under their headings, as its ticket page shows them. Each file adds `tracker`, `saved` (when it was read), `changed` (the tracker's last-changed time it was read at) and, after a failed read, `failed` (why, in `unreadWhy`'s words, and when). A field the tracker can't give (`url`, `changes`, `changed`) is left out, never an empty string. `acc analyze --ticket` and `acc draft criteria --ticket` take the file as it is.
- **Card times.** Each card now carries `updated`, from the card list the board already reads: Jira's and Jira Service Management's `updated`, GitHub's `updatedAt` (issue list and Project items), Azure DevOps' `System.ChangedDate` in the work-item batch, monday.com's `updated_at`, and a Slack thread's newest reply (`latest_reply`, else its own message). No extra read. A card whose list gives none is read when it has no saved copy, and again once its copy is a day old (`UNTIMED_MAX_MS`). Every tracker above gives one, so only a list that leaves it out meets this rule.
- **Reads.** The board draws from `boards.json` at once, then loads as before. After it has drawn (`Trackers.loadBoards` holds the queue while it runs), `TicketSaver.follow` queues the cards whose last-changed time moved since their saved copy, and those with no copy, the board on show first. The queue reads one ticket at a time, 1.5 s apart (`SAVE_SPACING_MS`), and waits while anything the person does runs: a ticket they open, Make a plan, drafting criteria, Track, or a board load. A board switch puts its tickets first. A ticket the person opens is read then, ahead of the queue; where the last load showed it and its saved copy is out of date, that read is saved and it leaves the queue. Closing a project or the window stops its queue.
- **Following the board.** Only tickets on a board that loaded are kept (D-072): one that leaves the board is removed at the next load, and one whose background read says it is outside the place is removed then. A board that failed to load keeps its tickets. A tracker whose settings changed drops the old tracker's tickets. Signing out removes the saved tickets of each open project's tracker on that site that has no sign-in left; one that falls back to its site's sign-in (GH-79) keeps them.
- **Commands.** `acc board` lists the saved boards (columns and cards) and `acc ticket <key>` shows one saved ticket. Each says when it was saved in words ("saved 12 minutes ago") and whether the board's last load found it changed since, so a newer read waits. Both take `--json`, read only the state folder, and never call a tracker. With nothing saved, both say to open the project in the Command Center.
- **No fallback.** `acc analyze` and `acc draft criteria` do not read a saved ticket on their own when no `--ticket` is given. The Command Center hands them the ticket it reads, as before; a session passes the saved file (`acc ticket <key> --json` gives its path as `file`). A silent fallback would let a plan read a copy that waits to be read again without saying so.
- **The intake skill** reads the saved board and tickets first, and uses a connector only when nothing is saved.
- Checked by `extension/test/ticket-saver.test.ts` (reads counted: one file a card on a first load, none when nothing changed, exactly the two that changed; reads only after the board drew; an opened ticket first; a stopped queue goes on; a failed read keeps the last good copy; leaving the board, a changed tracker and a sign-out remove; no stand-in token in any written byte), `packages/core/test/saved-tickets.test.ts` (the shape both `--ticket` readers take, fields left out, current or not, the session's board view), `packages/cli/test/saved.test.ts` (both commands, the saved time, a waiting change, nothing saved), and one test each in `packages/core/test/trackers.test.ts`, `jira-queue.test.ts` and `slack-board.test.ts` (each card list's time, in its one read).
