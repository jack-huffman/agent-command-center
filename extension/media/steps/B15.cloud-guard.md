# The push guard is committed

`B15.cloud-guard`

A cloud session runs the repo's own .claude/settings.json hooks and not the Command Center's plugin, so the guard that refuses a push to any branch but the task's, and the git pre-push hook it installs in the clone to check the push itself, are scripts the repo carries, and only what's committed reaches the cloud (GH-69).

## How to fix it

Do it opens Set up cloud builders; in The push guard: Do it commits the guard's three files on the branch the cloud clones, and Push… pushes that branch once you say so.

---

The step ticks itself when its check passes. **Check** re-runs it at any time, and so does **Check the setup**, from the command palette.
